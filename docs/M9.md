# M9 — 产品化与可观测性（Distribution & Observability）

> 提案状态:**三支柱全部验收**。A 分发 ✅(`tau --version`/`doctor`/`config` + `bun run build:all` 五平台单二进制);B 可观测性 ✅(`tau log`/`replay`/`export`,严格只读);C 会话治理 ✅(`tau sessions` + `tau schedule` 定时目标)。出口断言 #19–#22 落地,`tau eval` 22/22 passed(二进制内同样 22/22)。
> 承接:M0–M8 能力栈已完整;审计7(docs/audit7.md)已补齐契约面(deny/thinking/artifact/recent)。

## 0. 定位

**一句话**：M8 之后 tau 已是能力完整的开发者预览 monorepo；M9 把它变成"能日常跑、能排查、能分发"的可用产品。**不新增任何 agent 能力**（严守宪法第一条"agent 只是增强层"），只做横向基建，且全部建于既有的四契约 / Event 底座之上——零宪法冲突。

## 1. 为什么是现在（而非 M10 再做）

- **D6 自举验收**要求 tau 能可靠地"tau 开发 tau"；当前仍是 dev 态 monorepo，缺分发与治理，自举不可持续。
- PLAN「远期选项」已点名**单二进制分发**（kimi-code 高价值借鉴，Bun `--compile`）；审计7 刚补 `thinking`/`artifact` 等契约面，为"可观测投影"铺好路。
- 全部能力都依赖 `Event` 流 + `store`，可观测性 / 治理是"免费"的横切层——**不引入新边界、不改动依赖方向**。

## 2. 范围（3 个支柱）

### 支柱 A：单二进制分发（Distribution）

- `app` 包：`Bun --compile` 单二进制；subcommand 懒加载（交互面**不 import TUI**，与 M5/M7 经验一致：交互面与内核解耦）。
- `tau doctor`：自检——契约 JSON Schema 校验 / `store` 迁移可达 / 配置合法 / capability 门规则生效 / 四契约 wire 格式往返一致。
- 配置管理：`tau config get/set`，落 `store.kv`（或 XDG 配置），**禁止明文 secrets 落盘**（副作用法：配置写也只经 store/SystemCall 路径）。
- 双发：二进制优先 + npm 包（D5 已定 ③ 双发）。
- **出口标准**：干净机器上单二进制 `tau --version` / `tau doctor` 跑通；CI 产出可下载 artifact。

### 支柱 B：可观测性（Observability，隐私优先）

- `tau log <sessionId>`：从 `store.events.replay` 导出事件流（JSONL，可 grep / 重放）；支持按 `kind` / 时间窗 / `requestId` 过滤。
- `tau replay <sessionId>`：重放 → `project()` → 渲染时间线，复用契约 `assertReplay` / `assertDualView` 不变式（验证"重放重建投影 = 快照"）。
- 会话归档导出：`tau export <sessionId> --format jsonl|markdown`，**含压缩摘要溯源**（严守宪法第七条"压缩是交换不是丢弃"：全文永远可 retrieve）。
- **本地优先**：所有观测产物落本地，绝不外发。对照 PLAN「不吸收 opencode 遥测/账户/SST 基础设施」——可观测 ≠ 遥测，严禁 phoning home。
- **出口标准**：eval 断言 #19 事件导出可重放一致 / #20 `doctor` 自检覆盖关键不变量。

### 支柱 C：会话治理（Session Governance）

- `tau sessions`：`list` / `resume` / `archive` / `delete`——`delete` 走 **archive 而非物理删**（沿用 M4 `audit_archive` 思路：不删历史，只标记）。
- 定时目标（Scheduled Goals）：cron 驱动 goal 完成（openchamber 借鉴，中价值）；复用 `orchestrate` 的 goal 判定 + `store` 持久化，不新写内核。
- 多会话隔离已在 M4 验证，此处只补**治理面**，不碰 session 内核。
- **出口标准**：eval 断言 #21 会话归档后可重放恢复 / #22 定时目标到点触发判定。

## 3. 宪法对照（无冲突）

| 宪法 | M9 遵守方式 |
|---|---|
| 第二条 四契约 / 第三条 双视角 | 可观测性**只读** Event / 投影，不新增信息面；UI⊆投影 仍成立 |
| 第四条 依赖法 | 新代码只在 `app` / `surface` / `store` 内，不改依赖方向；`app` 仍唯一拼装点 |
| 第五条 副作用法 | 配置写经 `store`（SystemCall 路径），无旁路；无隐藏命令 |
| 第七条 记忆法 | 导出含压缩溯源；archive 不物理删 |
| 第九条/十条 性能/多语言 | `log`/`replay` 走流式 + 分页；相关 SPEC 补「性能与算法 / 多语言」节 |

## 4. 候选后续里程碑（roadmap 延伸，非本次范围）

- **M10 插件市场生态**：registry server + 发布 / 签名 / 审核 / 信任分级落地（M8 已留 `TrustLevel` 钩子，"为后续市场做准备"）。
- **M11 认知与长程记忆**：`thinking`/`artifact` 渲染进 TUI（闭环审计7 P1-2/P1-3）、压缩质量升级（LLM 摘要 policy 默认化）、跨会话 episodic memory、self-reflection 循环。
- **M12 多代理编排深化**：agent teams / 任务分解 DAG / 人在环工作流（M8 的 multirun + codemode 之上）。

## 5. 风险

- **单二进制动态插件**：M8 已声明"发布版插件经外部子进程协议接入（与 MCP 同构），内联 JS 插件仅开发模式"——M9 分发必须固化该结论，禁止动态 `load` 破坏单二进制。
- **可观测性滑向遥测基建**：严守本地优先、不外发；不引入账户 / 云端上报。
- **范围膨胀**：M9 只做横向基建，不碰 agent 能力内核（对照风险清单"范围膨胀"）。

## 7. 落地记录(实现与提案的差异)

| 项 | 提案 | 实际 | 为什么 |
|---|---|---|---|
| cron 解析 | 轻量库(`croner`) | **自实现** `orchestrate/src/cron.ts`(五段最小子集 ~120 行) | tau 只需分钟粒度本地时区;引依赖违背"不引入新依赖",成本高于收益 |
| 定时驱动 | `schedule(cron, prompt)` 常驻 | `tau schedule run` 一次性检查,由**系统 cron** 每分钟拉起 | tau 不做常驻守护进程;`lastRunAt` 作幂等锚点,重复调用不重复触发 |
| 调度表存储 | 未定 | 落 `store.kv`(键 `schedules`),不新建表 | 副作用唯一出口;调度表规模小,不值得新 schema |
| 观测命令实现 | 未定 | 只 `openStore` 直读,**绝不 `compose()`** | compose 会建 session 并可能写 recovery 事件——"看一眼"就污染被观测日志 |
| `sessions delete` | delete = archive | 同提案,且 CLI 明示"历史不物理删,仍可 replay/resume" | 宪法第七条 |
| 双发(二进制 + npm) | D5 已定 | 先落二进制(5 平台);npm 包待 registry 决策 | npm 发布涉及账号/签名,不阻塞 M9 出口 |
| `@tau/tui` 依赖 | 未提 | 补进 `app` 依赖 | 懒加载 `import()` 也必须是声明依赖,否则 `--compile` 直接 resolve 失败(且 dev 态交互模式本就跑不起来) |
